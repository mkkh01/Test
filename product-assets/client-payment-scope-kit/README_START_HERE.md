# Client Payment & Scope Protection Kit

## Start Here

This kit is designed for freelancers, consultants, creators, and small agencies who want to protect project revenue without making client communication hostile.

The kit follows one simple workflow:

```text
Qualify the client → define the project → secure the deposit → control changes → invoice clearly → follow up → document delivery
```

It is not a legal contract and it does not guarantee payment, revenue, or dispute outcomes. It is a practical business-operating system that helps you create clear written expectations and consistent records. Adapt legal, tax, cancellation, and late-fee language to your country and situation.

## What the Forms Actually Do

The form files are practical Markdown templates for adapting into a document or online form. They include clear fields, required decisions, and conditional guidance. In the web store, the product intake form is implemented by the private application backend; the downloadable files are reusable client-facing templates and do not transmit data anywhere by themselves.

## Five Rules That Make the Kit Work

### 1. Never start without a written scope

The proposal explains the recommended approach. The Scope of Work defines exactly what will be delivered, what is excluded, how many revisions are included, and how acceptance will be determined.

### 2. Never treat a new request as automatically included

A request is either included in the approved scope or it becomes a Change Request. Do not argue about whether a request is “small.” Check whether it changes the deliverables, quantity, platform, deadline, or approved direction.

### 3. Link payment to a clear event

Use a deposit before work starts and milestone payments for longer projects. Every payment should have an amount, due date, trigger, invoice number, and status.

### 4. Keep one decision-maker

The client should nominate one person who consolidates feedback and gives approval. This prevents contradictory instructions from multiple stakeholders.

### 5. Keep evidence, not drama

Save the approved proposal, scope, change requests, invoices, payment references, delivery link, and acceptance confirmation. Use factual language and avoid threats, exaggerated claims, or promises you cannot control.

## A 30-Minute Setup

1. Replace the brand placeholders in the files with your name, email, website, and payment details.
2. Choose your default deposit percentage and revision limit.
3. Choose one primary communication channel.
4. Open the Excel tracker and replace the example row with your project.
5. Save a clean master copy before customizing the first client version.
6. For every project, duplicate the master and rename it with the client and project reference.

## Recommended Default Settings

These are starting points, not universal rules:

| Setting | Suggested default |
|---|---|
| Deposit | 50% before work begins |
| Milestone billing | 25% after an agreed milestone |
| Final payment | 25% before final editable/source-file transfer |
| Revision rounds | 2 consolidated rounds |
| Client feedback window | 3 business days |
| Proposal validity | 14 calendar days |
| Payment reminder cadence | Due date, +3 days, +7 days, +14 days |
| Communication owner | One named client decision-maker |

## How to Use the USDT Option

If you accept USDT, complete the payment section with one network only and double-check the public receiving address before publishing the invoice. Never place a private key or seed phrase in these files. The buyer should verify the network and address before sending. You should verify the transaction on the blockchain before marking an invoice as paid.

## Quality Check Before Sending

- [ ] The client name, project name, dates, and reference are correct.
- [ ] The client’s desired outcome is written in plain language.
- [ ] Each deliverable has a quantity, format, and acceptance check.
- [ ] Exclusions are specific.
- [ ] Revision limits are visible.
- [ ] Client responsibilities and feedback deadlines are visible.
- [ ] Payment amounts, triggers, due dates, and invoice IDs match.
- [ ] Change Requests require written approval before additional work starts.
- [ ] No unsupported revenue guarantee or legal threat is included.
- [ ] No private key, seed phrase, password, or card details are included.
- [ ] A clean copy has been saved for reuse.
